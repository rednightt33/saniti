## 4. Cara kerja yang sudah terbukti (resep)

- **Migrasi:**
  1. Generate lewat skrip (`scripts/generate_tool_catalog_migration.py`, `generate_ai_method_guide_migration.py`). Migrasi lama tidak pernah diedit.
  2. Buat job sementara: `railway add --service X --variables 'DATABASE_URL=${{Postgres.DATABASE_URL}}' --variables MODE=DRYRUN`.
  3. `railway up <dir> --path-as-root --service X --environment dev --detach`, lalu ganti `MODE=APPLY` dengan `--skip-deploys` dan `railway up` lagi.
  4. Baca balik hasilnya, lalu `railway service delete --service X --environment dev --yes`.
  5. Tambah checksum ke `APPLIED.sha256`.
- **Smoke test Governor** (servisnya internal): pakai job sementara dengan variabel referensi `GOVERNOR_URL=${{market-ai-orc.SQL_GOVERNOR_URL}}` dan `GOVERNOR_KEY=${{market-ai-orc.SQL_GOVERNOR_API_KEY}}`. Jangan pernah mencetak nilainya.
- **Tes Governor lokal:** butuh Postgres. Mulai sebagai user postgres: `pg_ctl -D <data> -o '-p 55432 -k <dir>' start`, lalu set `GOVERNOR_TEST_POSTGRES_URL="postgresql://postgres@127.0.0.1:55432/postgres"`. Pakai TCP; URL lewat unix socket gagal.
  - Kontainer cloud bersifat sementara. Venv dan data Postgres lama di scratchpad mungkin hilang, jadi buat ulang dari `requirements` tiap app.
- **Dokumen yang di-generate** (wajib saat alat, model atau router berubah):

  - `scripts/generate_ai_models_doc.py`;

  Tes drift akan gagal bila dokumen ini tidak ikut diperbarui.

  - Tes khusus: `tests/test_prompt_audit.py`.
- **Deploy:** push `main` memicu deploy per service (watch pattern `/apps/<svc>/**`). Klaim SUCCESS hanya setelah deployment untuk commit itu berstatus SUCCESS (`railway deployment list --json`, lihat `meta.commitHash`).
